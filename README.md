## Что это

Обычные темы VS Code меняют только цвета. Плагины «картинка на фон» ставят одну статичную
картинку на весь редактор — и на этом всё.

**MoonLight custom-bg** идёт дальше: это один самодостаточный скрипт, который подгружается в
интерфейс VS Code через расширение [`be5invis.vscode-custom-css`](https://marketplace.visualstudio.com/items?itemName=be5invis.vscode-custom-css)
и добавляет полноценную панель оформления прямо в редактор.

| | Обычная тема | Плагин «картинка на фон» | MoonLight custom-bg |
|---|---|---|---|
| Своя картинка | нет | да (одна на всё) | **да, отдельно на редактор / сайдбар / панель** |
| Наборы с палитрой | нет | нет | **да, 7 наборов, у каждого свой акцент** |
| Слайдшоу по таймеру | нет | нет | **да, с предзагрузкой (без «моргания»)** |
| Настройка без правки файлов | частично | нет | **да, панель прямо в редакторе** |
| Эффекты (Ken Burns, стекло, виньетка) | нет | нет | **да** |
| Виджеты статусбара | нет | нет | **да: часы, помидор-таймер, частицы** |
| Внешние зависимости | — | — | **нет (0 npm-пакетов)** |

## Возможности

Всё настраивается в панели **«Фон и дизайн»** (кнопка `BG N` в статусбаре):

- **Наборы фонов** — 7 наборов (картинки для редактора / сайдбара / панели); выбор набора
  или «случайно». У каждого набора **свой акцентный цвет** — переключение перекрашивает
  интерфейс под палитру набора.
- **Слайдшоу** — авто-смена набора по кругу через заданный интервал (1–120 мин); следующий
  набор **предзагружается**, чтобы смена шла без «моргания».
- **Яркость по зонам** — насколько ярко проступает картинка в каждой зоне, плюс
  **авто-яркость editor**: для светлых артов прозрачность занижается сама, чтобы код оставался
  читаемым.
- **Картинка** — акцентный цвет интерфейса (курсор, скроллбар, вкладки, рамки…, свой на набор)
  и фильтры фоновой картинки **по зонам**: выбираешь зону — под неё настраиваются вписывание
  (cover / contain), яркость / насыщенность / размытие. Битая картинка (404) заменяется акцентной
  подложкой.
- **Эффекты** — Ken Burns, матовое стекло, виньетка, свечение курсора, живой контур и др.
- **Терминал** — шрифт (Nerd), лигатуры, жирность, свечение, цвет и размер курсора / выделения.
- **Виджеты статусбара** — часы, таймер-помидор, летящие частицы (перекрашиваются под акцент).
- **Экспорт / импорт** настроек в JSON. Всё запоминается между запусками.

## Наборы фонов

У каждого набора три картинки (редактор / сайдбар / панель) и собственный акцентный цвет.
Акцент можно переопределить вручную — правка хранится только для этого набора.

| # | Набор | Акцент |
|---|-------|--------|
| 0 | Маки | `#f38ba8` |
| 1 | Пурпур | `#cba6f7` |
| 2 | Кровавая луна | `#f38ba8` |
| 3 | Лунная тушь | `#94e2d5` |
| 4 | Синяя ночь | `#89b4fa` |
| 5 | Пурпурный сон | `#cba6f7` |
| 6 | Коты и луна | `#f5c2e7` |

> Палитра акцентов — в духе [Catppuccin](https://github.com/catppuccin/catppuccin). Запас
> нераспределённых картинок лежит в корне `assets/` — из них можно собирать новые наборы.

## Установка

Скрипт подгружается расширением **be5invis.vscode-custom-css**, а не устанавливается как обычное
расширение из Marketplace.

1. **Поставь расширение** `be5invis.vscode-custom-css` (через Marketplace или
   `code --install-extension be5invis.vscode-custom-css`).

2. **Склонируй репозиторий** в удобную папку:
   ```bash
   git clone https://github.com/moonlivedt-oss/custom_VScode.git
   ```

3. **Пропиши путь к `custom-bg.js`** в `settings.json` VS Code
   (`Ctrl+Shift+P` → *Preferences: Open User Settings (JSON)*):
   ```jsonc
   "vscode_custom_css.imports": [
     "file:///d:/Desktop/components/vscode-bg/custom-bg.js"
   ]
   ```
   > Путь — в формате `file:///` c абсолютным адресом до **твоего** `custom-bg.js`.
   > На Windows буква диска в нижнем регистре, слэши прямые (`/`).

4. **Включи** кастомный CSS: `Ctrl+Shift+P` → **Enable Custom CSS and JS**.

5. **Полностью перезапусти** VS Code (`File → Exit`, не просто закрыть окно).

> Внимание: после каждого обновления VS Code расширение custom-css нужно включать заново
> (`Enable Custom CSS and JS` + перезапуск) — это ограничение самого механизма, не плагина.

**Проверка версии:** `Help → Toggle Developer Tools` → вкладка Console → строка
`[MoonLight custom-bg] v10 …`.

## Как пользоваться

После установки в статусбаре (правый нижний угол) появится кнопка **`BG N`**, где `N` — номер
активного набора. Клик по ней открывает панель **«Фон и дизайн»**:

- **Наборы** — плитки-чипы с превью; клик выбирает набор, кнопка «случайно» включает случайный
  выбор при старте. Красный «!» на чипе = картинка набора не загрузилась.
- **Слайдшоу** — включить авто-смену и задать интервал.
- **Картинка** — выбрать зону (editor / sidebar / panel) и настроить под неё вписывание, яркость,
  насыщенность, размытие; отдельно — акцентный цвет набора.
- **Эффекты / Терминал / Виджеты** — сворачиваемые секции с тумблерами и ползунками.
- **Экспорт / импорт** — сохранить настройки в JSON и вернуть их обратно (в т.ч. на другой машине).

Панель можно перетаскивать за заголовок; позиция запоминается. Закрыть — `Esc` или клик мимо.

## Сборка

Модули **не** используют `import`/`export` — они живут в одной области видимости (как раньше в
монолите). `build.js` склеивает их по порядку из списка `FILES` внутрь одного IIFE. Порядок важен:
сначала данные / состояние, потом CSS, UI, виджеты, старт.

```bash
node build.js        # → пересобирает custom-bg.js
```

**Цикл правки:**

1. Правишь файл в `src/**`.
2. `node build.js`.
3. VS Code: `Ctrl+Shift+P` → **Enable Custom CSS and JS**.
4. Полный перезапуск VS Code (`File → Exit`).

> Зависимостей нет — нужен только Node.js для запуска `build.js`. `npm install` не требуется.

## Добавление набора

Картинки лежат в `assets/`: фоны, входящие в набор, — в подпапках `editor/`, `sidebar/`, `panel/`;
ещё не разложенные — в корне `assets/`. Поддерживаются png / jpg / gif.

Чтобы добавить набор N:

1. Положи 3 картинки в `assets/editor/`, `assets/sidebar/`, `assets/panel/`
   (например `editor_7.jpg`, `sidebar_7.jpg`, `panel_7.jpg`).
2. Добавь запись в массив `SETS` в `src/core/config.js`:
   ```js
   { editor: "assets/editor/editor_7.jpg",
     sidebar: "assets/sidebar/sidebar_7.jpg",
     panel:   "assets/panel/panel_7.jpg",
     accent:  "#f5c2e7" }   // свой акцентный цвет набора
   ```
3. `node build.js`.
4. VS Code: `Ctrl+Shift+P` → **Enable Custom CSS and JS** → полный перезапуск.

Пути в `SETS` указываются относительно `IMG` (базовый путь к папке плагина; вычисляется
автоматически из адреса самого скрипта). Health-check в панели пометит чип красным «!», если
картинка набора не грузится.

## Безопасность

Весь внешний конфиг (из `localStorage` и при **импорте** JSON-файла) проходит через `mergeCfg` в
`src/core/config.js`, который принимает только значения известного типа и диапазона:

- **шрифт терминала** — только из белого списка `TERM_FONTS` (`safeFont`);
- **цвета** (курсор / выделение) — строго `#rrggbb` (`isColor`, регэксп);
- **числа** (яркость, сила эффектов, вес / свечение) — зажимаются в допустимые диапазоны (`clampNum`);
- **флаги** — только `boolean`; `mode` — `"random"` или индекс набора в диапазоне.

Дополнительно (defense-in-depth):

- **prototype pollution** — JSON разбирается через `safeParse` (reviver отбрасывает ключи
  `__proto__` / `constructor` / `prototype` ещё до `mergeCfg`);
- **импорт файла** — отсекается по размеру (>256 КБ), т.к. валидный конфиг весит килобайты.

Это закрывает главный вектор — **CSS-инъекцию** через подменённый / чужой файл настроек (например
попытку «вырваться» из `font-family:'...'` и дописать произвольные правила). `buildCSS`
дополнительно санитизирует шрифт и цвета **повторно** перед вставкой в CSS.

> Инъекция стилей делается через `textContent` элемента `<style>` (не `innerHTML`), так что
> HTML-инъекция невозможна; значения-числа и цвета — единственное, что могло бы повлиять на CSS,
> и они провалидированы.
