# Участие в разработке

Спасибо за интерес к MoonLight custom-bg! Проект небольшой и без зависимостей — влиться легко.

## Быстрый цикл

```bash
git clone https://github.com/moonlivedt-oss/custom_VScode.git
cd custom_VScode
# зависимостей нет — npm install не требуется
node build.js         # собрать custom-bg.js из src/**
node test/smoke.js    # прогнать смоук-тест
npm run check         # то и другое одной командой
```

Рекомендуется один раз поставить локальный pre-commit хук — он сам пересобирает артефакт и
гоняет smoke перед каждым коммитом, чтобы не закоммитить рассинхрон:

```bash
npm run hooks
```

## Как устроен код

- Исходники — в `src/**`. Один модуль = одна ответственность; ни один файл не должен
  разрастаться до «всего понемногу». Текущая карта:

  | Слой | Файлы | За что отвечает |
  |---|---|---|
  | `core/` | `util` · `sets` · `config` · `state` · `scrape` · `env` · `i18n` | санитизация значений, каталог наборов, схема и загрузка конфига, выбор активного набора, чтение данных из DOM, среда загрузчика, локализация |
  | `fx/` | `color` · `image` · `sets-bg` · `readability` · `blocks` · `css` · `style` · `shader` | цвет и палитра (OKLab), проба и кэш картинок, источники фона зоны, читаемость кода, таблица CSS-блоков эффектов, сборка листа, применение стиля и переменные, WebGL-фон |
  | `ui/` | `dom` · `info` · `controls*` · `io` · `looks` · `theme-export` · `diagnostics` · `quick` · `statusbar` · `panel*` | хелперы и подсказки, контролы по вкладкам, обмен конфигом и образами, экспорт темы, диагностика, быстрый переключатель, кнопка BG, каркас и наполнение панели |
  | `widgets/` | `extras` · `particles` · `perf` · `pet` · `auto` | виджеты статусбара, частицы и шлейф, бюджет производительности, питомец, авто-смена фона |
  | — | `boot.js` | запуск, самолечение, хоткеи, синхронизация окон |

- Модули **не** используют `import`/`export`: они живут в одной области видимости и склеиваются
  `build.js` в один файл `custom-bg.js` внутри общего IIFE. **Порядок склейки важен** — он задан
  списком `FILES` в `build.js` (единый источник правды, его же читает смоук-тест). Объявления
  функций поднимаются, поэтому вызывать «вперёд» можно; а вот исполняемые строки верхнего
  уровня (`var cfg = loadCfg()`, дозагрузка ген-наборов) зависят от порядка — их не переставляй.
- `custom-bg.js` — **сгенерированный** файл. Правь `src/**`, затем `node build.js`. Коммить
  `src/**` и пересобранный `custom-bg.js` **вместе** — CI проверяет, что они совпадают.
- Стиль: осторожный ES5-совместимый JS (плагин исполняется в разных версиях воркбенча),
  оборонительные `try/catch` вокруг работы с DOM, комментарии — на русском.
- Комментарий объясняет **почему**, а не пересказывает код: причину неочевидного решения,
  подводный камень VS Code, формулу. Не нужно: пересказ следующей строки, история правок и
  номера версий (для этого есть CHANGELOG), повтор того, что уже сказано в шапке файла.
- **Без эмодзи** — нигде: ни в коде, ни в UI, ни в Markdown, ни в сообщениях коммитов.

## Тесты

- **Смоук** (`node test/smoke.js`) — обязателен. Собирает модули, выполняет их в vm-песочнице с
  мини-DOM-стабом и проверяет генерацию CSS + инварианты (`FX_LIST ↔ DEFAULTS.fx`, `INFO ↔ INFO_EN`,
  диапазоны, локализацию, профили и т.п.). Ловит кросс-модульные `ReferenceError`, которые
  `node --check` не видит. Прогоняй после любой правки в `src/**`.
- **e2e** (`npm run test:e2e`, Playwright) — по желанию: реальный Chromium открывает панель в
  тестовой фикстуре и проверяет живой DOM (кнопка, инжект, локализация, быстрый переключатель,
  CSS-переменные, здоровье селекторов). Фикстура ставит `window.__MLBG_TEST_HOOKS__ = true` —
  только при этом флаге плагин открывает наружу узкий мост `window.__mlbgTest`; в реальном VS Code
  никакой глобальной поверхности не появляется. Playwright — dev-зависимость, в основной поток не входит.
- Добавляешь фичу — добавь и проверку в `test/smoke.js` (там мини-линтер инвариантов, дополняй его).
- **Мёртвый код** (`npm run lint:dead`) — входит в `npm run check`. Находит объявления без
  ссылок, ключи локализации без строк в коде, подсказки `INFO` без потребителя и эффекты из
  `FX_LIST` без реализации.

## Локализация

UI двуязычный (RU/EN). Русский — исходный язык и **ключ** словаря. Любую видимую строку
оборачивай в `t("...")`; для нового текста добавь перевод в `EN` (`src/core/i18n.js`), а для
подсказок — пару в `INFO` / `INFO_EN` (`src/ui/info.js`). Смоук-линтер требует, чтобы у каждого
`INFO` была пара в `INFO_EN` — иначе тест упадёт.

## Добавить набор фонов

Кратко (подробнее — в разделе «Добавление набора» в [README](README.md)):

1. Положи картинки в `assets/editor|sidebar|panel/` (или сделай набор градиентным/процедурным/
   шейдерным без ассетов — см. поля `grad` / `proc` / `shader` в `SETS`).
   Проще всего — **мастер-кадр**: один файл 21:9 на весь набор, зоны получаются вырезами.
   `node scripts/import-master.js <файл|папка> --name "Имя"` измерит кадр, посчитает акцент в
   OKLab, предложит вырезы, скажет контраст кода к вырезу редактора и закодирует JPEG в
   `assets/sets/` (нужен ffmpeg в PATH). Останется вставить напечатанную запись в `SETS`.
2. Добавь запись в массив `SETS` в `src/core/config.js` (укажи `accent` — акцент интерфейса).
3. `node build.js && node test/smoke.js` — смоук проверит счётчики и инварианты наборов.

## Pull request

1. Ветка от `main`, понятное имя.
2. `npm run check` — зелёный (сборка + smoke + линтер мёртвого кода).
3. `custom-bg.js` пересобран и закоммичен вместе с `src/**`.
4. Опиши, что и зачем; если менял UI — приложи скриншот.
5. Скриншоты панели можно пересоздать `npm run screenshots` (нужен Playwright).

CI прогонит smoke на Node 18/20, проверит синтаксис модулей и что артефакт пересобран из `src/`.
